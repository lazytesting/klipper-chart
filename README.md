# Ender 3 Klipper configuration

For an Ender 3 with a Creality V4.2.7 board, Sprite direct drive, KevinAkaSam belt-driven Z and BLTouch. The files contain hardware settings that need measurements or confirmation on the actual printer. The installer blocks activation while any `REPLACE_...` entries remain.

## File layout on the Pi

```text
~/printer_data/config/
├── printer.cfg                      # Local entry point, MCU path and SAVE_CONFIG
├── moonraker.conf                   # Existing Moonraker configuration
├── ender3-update.conf               # Local Update Manager entry
└── ender3/                          # Git checkout of lazytesting/klipper-chart
    ├── config/printer-managed.cfg
    ├── config/hardware/
    └── config/macros/
```

Edit the managed files on GitHub. Klipper's regular include chain defines fixed hardware and macros. The local top-level `printer.cfg` seeds BLTouch's `z_offset` and both heater `control` values. Klipper comments out those seeds and writes the calibrated values in its generated block when you run `SAVE_CONFIG`. Keep `z_offset`, heater `control` and `pid_Kp`/`pid_Ki`/`pid_Kd`, and every `[bed_mesh PROFILE]` section out of managed includes. The managed `[bed_mesh]` section defines probing geometry. Keep the autogenerated block last in `printer.cfg` and leave the root file writable by Klipper. [Klipper config writer](https://github.com/Klipper3d/klipper/blob/master/klippy/configfile.py)

## 1. Confirm hardware and prepare GitHub

Use the running config and machine as references. Some items may differ on a modified Ender 3 even when the board model matches.

| Check | Where and what to confirm |
| --- | --- |
| MCU | Run `ls -l /dev/serial/by-id/` on the Pi. Use the existing working device path. Use `/dev/serial/by-path/` if the bridge has no unique ID. Verify the chip marking, firmware protocol and transport against the current setup. Upstream's V4.2.7 example uses STM32F103, a 28 KiB bootloader and USART1 over the board's USB-to-serial bridge. Keep the working firmware. |
| X and Y | Confirm motor directions, endstop states, switches at the configured origins, travel limits with the Sprite installed, and 40 mm rotation distance for stock 20-tooth GT2 X/Y pulleys. Adjust any origin or direction that differs. |
| Belted Z | Confirm motor wiring and direction, motor step angle, microsteps, pulley tooth counts, belt pitch, and collision-free Z limits. For a simple reduction with a moving belt driven by an output pulley, effective Z travel per motor turn is belt pitch × output pulley teeth × motor reduction pulley teeth ÷ driven reduction pulley teeth. Confirm the formula matches your exact belt routing and measure actual travel. This file expects the effective distance in `rotation_distance` with no Z `gear_ratio`. |
| Sprite | Confirm extrusion direction, motor step angle, nozzle diameter, gearbox ratio and calibrated distance. The upstream S1 config uses `42:12` with `26.359` mm. Use that pair only if applicable. A previously calibrated effective distance with no ratio can be represented with `gear_ratio: 1:1`. |
| BLTouch | Trace both signal wires and confirm connector pin order, 5 V and ground, pull-up and polarity. Dedicated probe header signals are normally `^PB0` and `PB1`. If the sensor lead uses the original Z-stop header, verify the actual input, normally `^PA7`. The Z endstop is `probe:z_virtual_endstop`. Verify deploy, stow and trigger with Z safely away from the bed. |
| Probe reach | Measure signed probe XY offsets from the nozzle. Set `home_xy_position` in nozzle coordinates so the probe is over the bed. Set mesh bounds in probe coordinates. For each mesh corner, subtract the probe offsets to obtain the nozzle coordinates and verify those are within actual axis travel. Verify clearance for `z_hop` and `horizontal_move_z`. The mesh move height must exceed the probe Z offset. |
| Heaters and fans | Verify sensor models, wiring, rated temperatures for the actual hotend and bed, and any separate heatsink fan wiring. Confirm that both readings are plausible at room temperature and respond to the correct component before commanding heat. Confirm that the part fan and hotend cooling work. |

Record the confirmed fixed settings in `config/hardware/` and merge them into `main`. Before installation, also review the existing `printer.cfg` and includes for features you still use, such as filament sensors, input shaping, a display, a separate heater fan or slicer-specific macros. Port needed definitions into the Git repo. The bundled Mainsail config uses Klipper's built-in pause and resume and a cancel macro that turns off heat and part cooling. Remove duplicate definitions when porting macros. Reconfirm the slicer's start and end commands.

[Creality V4.2.7 pin map](https://github.com/Klipper3d/klipper/blob/master/config/generic-creality-v4.2.7.cfg) · [Sprite reference](https://github.com/Klipper3d/klipper/blob/master/config/printer-creality-ender3-s1-2021.cfg) · [KevinAkaSam belt conversion](https://github.com/kevinakasam/BeltDrivenEnder3) · [Rotation distance](https://www.klipper3d.org/Rotation_Distance.html) · [BLTouch checks](https://www.klipper3d.org/BLTouch.html)

## 2. Give the Pi read-only access

Run these commands over SSH on the Pi as the account that runs Moonraker. Confirm the account with `systemctl show moonraker -p User`. The installation scripts assume the standard single-instance service names and both services using this account's `~/printer_data`. Verify with `systemctl cat klipper moonraker`.

```bash
install -d -m 700 ~/.ssh
ssh-keygen -t ed25519 -f ~/.ssh/ender3_deploy -C 'ender3-moonraker' -N ''
cat ~/.ssh/ender3_deploy.pub
```

Use a new dedicated key. If that filename already exists, inspect it before choosing whether to reuse it or create a differently named key. In the repository's **Settings → Deploy keys → Add deploy key**, paste the public key and leave **Allow write access** unchecked. Keep the private key on the Pi. Add this host block near the top of `~/.ssh/config` before broad matching entries, then set the file to mode `600`.

```sshconfig
Host github-ender3
    HostName github.com
    User git
    IdentityFile ~/.ssh/ender3_deploy
    IdentitiesOnly yes
    BatchMode yes
    StrictHostKeyChecking yes
```

If GitHub is new to this account, collect its Ed25519 host key with `ssh-keyscan -t ed25519 github.com > /tmp/ender3-github-hostkey`. Check the output of `ssh-keygen -lf /tmp/ender3-github-hostkey` against GitHub's published Ed25519 fingerprint before appending the file to `~/.ssh/known_hosts`. Then verify access with `git ls-remote git@github-ender3:lazytesting/klipper-chart.git refs/heads/main` as the Moonraker account. The SSH alias in this command must match the clone's `origin` and Moonraker's configured `origin`.

[GitHub deploy keys](https://docs.github.com/en/authentication/connecting-to-github-with-ssh/managing-deploy-keys#deploy-keys) · [GitHub SSH host fingerprints](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/githubs-ssh-key-fingerprints)

## 3. Stage and install on the Pi

Back up the current config off the Pi before cutover. This archive preserves local files and symlinks. Back up any targets located outside the config directory separately.

```bash
umask 077
backup="$HOME/printer-config-before-ender3-$(date +%Y%m%d-%H%M%S).tar.gz"
tar -czf "$backup" -C "$HOME/printer_data" config
tar -tzf "$backup"
git clone git@github-ender3:lazytesting/klipper-chart.git ~/ender3-bootstrap
```

Set `SERIAL` and `Z_OFFSET` in your shell from the verified current machine before running the next command. Use the working Z offset only for the same probe and nozzle geometry. With no valid previous offset, use `0` as a temporary seed, verify the trigger and first Z descent in person, and calibrate before printing.

```bash
~/ender3-bootstrap/scripts/install.sh stage "$SERIAL" "$Z_OFFSET"
```

The script prints the candidate directory. It copies the old config files, creates a clean checkout inside the candidate, renders the local root file, and adds the Moonraker include. Compare the existing and staged `printer.cfg` and `moonraker.conf`. Existing calibration is intentionally kept in the backup for review. For unchanged hardware you may migrate verified Z offset, heater PID and a still-valid mesh profile into the staged local root. Put any migrated PID settings directly in the local sections in place of `watermark`, and keep generated mesh data in the final autosave block. Recalibrate anything affected by hardware or geometry changes. Treat the stage as a snapshot. If the active config changes after staging, stage again before applying.

For a symlinked config directory, a symlinked `moonraker.conf`, or an existing `ender3` checkout/updater entry, use the same templates manually. Back up the directory and symlink targets, review existing configuration and updater includes, clone the branch into `~/printer_data/config/ender3` or reuse the clean matching checkout, and make the backed-up local changes with both services stopped. Ensure there is exactly one Ender 3 updater stanza and one managed printer include.

Once installation is approved and the printer is idle and cold, set `STAGE` to the path printed by the script. The apply command moves the old config to a backup directory before installing the candidate and prints the backup path.

```bash
sudo systemctl stop moonraker klipper &&
    ~/ender3-bootstrap/scripts/install.sh apply "$STAGE" &&
    sudo systemctl start klipper moonraker
```

In Mainsail, check Klipper reports Ready, confirm no config errors in `~/printer_data/logs/klippy.log` and `moonraker.log`, and check for the `ender3` entry under Update Manager. If the service fails, use the rollback below. Keep the printer supervised during commissioning.

## 4. Commission and calibrate

1. Start cold. Verify temperatures, heaters, and fans using the manufacturer and Klipper checks. With clearance from the frame and bed, verify X/Y endstops with `QUERY_ENDSTOPS`, each axis direction with `STEPPER_BUZZ STEPPER=stepper_x` (then Y and Z), and BLTouch deploy/stow and triggered/open states following the BLTouch guide. On first Z homing, manually trip the deployed probe well above the bed and verify Z stops before allowing an actual probe of the bed. Keep a physical way to cut power within reach. [Klipper configuration checks](https://www.klipper3d.org/Config_checks.html) · [BLTouch initial tests](https://www.klipper3d.org/BLTouch.html#initial-tests)
2. Home safely and run `PROBE_CALIBRATE`, use `TESTZ` to set the nozzle height, then `ACCEPT` and `SAVE_CONFIG`. This restarts Klipper. Review the saved Z offset and rehome. [Probe calibration](https://www.klipper3d.org/Probe_Calibrate.html)
3. Once sensors and heaters are verified, run `PID_CALIBRATE HEATER=extruder TARGET=<verified-print-temperature>` and `PID_CALIBRATE HEATER=heater_bed TARGET=<verified-bed-temperature>` with real numeric, hardware-appropriate temperatures. Run `SAVE_CONFIG` after the tunes. Verify both local sections now have PID settings in the generated block.
4. After confirming reachable bounds and setting the Z offset, home and run `BED_MESH_CALIBRATE`. Save a named profile with `BED_MESH_PROFILE SAVE=printing` then run `SAVE_CONFIG`. After restart, use `BED_MESH_PROFILE LOAD=printing` in the slicer start G-code after homing if you want that profile used. Modern Klipper does not automatically load even the default profile. Recalibrate after changes to probe/nozzle geometry or bed tram. [Bed mesh profiles](https://www.klipper3d.org/Bed_Mesh.html#profiles)
5. Confirm `git -C ~/printer_data/config/ender3 status --porcelain` prints nothing. Use the backup script after calibrating so the saved values are available after an SD card failure.

## 5. Update from GitHub

Review and merge changes to `main` on GitHub. With the printer idle, refresh Mainsail's Update Manager and update the `ender3` entry. It follows the configured Git branch on the `dev` channel. The update entry deliberately has no managed services. Review changes and issue `RESTART` in Klipper when ready to load them. Existing local calibration persists across the pull. Recalibrate if you change anything that invalidates it. If you need to undo a bad commit, revert it on GitHub and update again. Keep the Pi checkout clean and avoid editing managed files in Mainsail. [Moonraker Git updates](https://moonraker.readthedocs.io/en/latest/configuration/#git-repo-configuration)

## 6. Recover from SD card failure or roll back an installation

After successful commissioning and after later calibration changes, take a snapshot while idle and with no update or calibration save in progress. Supply an existing backup directory, preferably mounted off the Pi. The snapshot contains the local config, including calibration, and records the Git remote, branch and commit. Copy the whole directory to off-device storage. Include any external symlink targets, optional Moonraker database backup, and any required service or OS settings in your separate system backup. The snapshot may contain private Moonraker settings. Store it privately.

```bash
~/printer_data/config/ender3/scripts/recovery.sh backup /path/to/existing/backup-parent
```

After SD card failure, reinstall Klipper, Moonraker and Mainsail, recreate or verify the service account and data paths, and create a new read-only deploy key on the replacement Pi. Revoke the old key in GitHub if it is no longer in use. Clone `~/ender3-bootstrap` as in the installation instructions. Restore external symlink targets before starting services.

```bash
~/ender3-bootstrap/scripts/recovery.sh stage /path/to/ender3-snapshot.DIRECTORY
```

Review the restored `printer.cfg`, verify the new Pi's serial device and correct it locally if needed, inspect Moonraker includes and service paths, and leave the generated calibration block last. The recovery checkout uses the saved commit and keeps tracking the configured branch. A rewritten branch that has lost the saved commit requires recovering that commit or reviewing a fresh install and recalibration. Then stop both services, run `~/ender3-bootstrap/scripts/recovery.sh apply "$STAGE"` with the recovery stage path, start both services, and repeat the machine checks before resuming prints.

For immediate rollback after a cutover, stop both services, move the active `~/printer_data/config` directory aside to a new path, then move the prior `config` directory from the printed `ender3-before.*` backup back to `~/printer_data/config`. Restart services after verifying the restored entry points. Preserve the displaced directory for diagnosis.
